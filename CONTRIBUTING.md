# How to Contribute

Thanks for your interest in contributing to Repository Agent Orchestrator! Here
are a few general guidelines on contributing and reporting bugs that we ask you
to review. Following these guidelines helps communicate respect for the time of
the contributors managing and developing this open source project. In return,
maintainers should reciprocate that respect when addressing issues, assessing
changes, and helping contributors finalize pull requests.

In that spirit of mutual respect, we endeavor to review incoming issues and
pull requests within 10 days and may close issues or pull requests after 60 days
of inactivity.

All interactions in this project are subject to our
[Code of Conduct](CODE_OF_CONDUCT.md). This includes creating or commenting on
issues and pull requests as well as participating in any project community
space.

## Reporting Issues

Before reporting a new issue, search the
[existing issues](https://github.com/cisco-open/repository-agent-orchestrator/issues)
to see whether it has already been reported or fixed.

When creating an issue, include a clear title and description, as much relevant
information as possible, and a test case or reproduction when practical. For a
bug, useful details include the project version or commit, operating system, Go
version, expected behavior, actual behavior, and sanitized logs. Never include
tokens, webhook URLs, authorization headers, or raw environment dumps.

**Do not report security vulnerabilities through a public GitHub issue. Follow
the private reporting process in [SECURITY.md](SECURITY.md).**

## Sending Pull Requests

Before sending a pull request, review existing issues and pull requests to see
whether the proposed change has already been discussed or implemented.

We expect pull requests to:

- address a focused problem
- explain what changed and why
- include tests for affected behavior
- report the verification that was run
- describe any configuration or operational impact

Read [DEVELOPMENT.md](DEVELOPMENT.md) for the development environment,
implementation rules, and commit conventions. Read [TESTING.md](TESTING.md) for
the required checks and test guidance.

Open an issue before starting a large feature, a breaking change, or a change
to the project's scope. Maintainers may ask for a large pull request to be split
into smaller, independently reviewable changes.

Unless explicitly stated otherwise, contributions submitted for inclusion in
Repository Agent Orchestrator are submitted under the Apache License, Version
2.0, as described in [LICENSE.txt](LICENSE.txt). Follow any additional
contribution checks configured by the repository owner, such as CLA, DCO,
sign-off, or Cisco open source release requirements.

## Other Ways to Contribute

Contributions are not limited to writing production code. You can also:

- triage open issues and help authors provide missing reproduction details
- review pull requests and test proposed changes
- improve documentation and examples
- write a test or add a missing case to an existing test
- suggest focused improvements that fit the project's local orchestration scope

Thanks again for your interest in contributing to Repository Agent
Orchestrator!
